# What To Do Next

## Step 1 - Pick a real practice site
Choose a public demo or sandbox website that you are allowed to test. Avoid submitting destructive or excessive requests to real commercial websites.

## Step 2 - Replace the fictional DemoShop results
Use the supplied templates to document your own testing. Employers care more about your thinking than the number of documents.

## Step 3 - Add evidence
Add screenshots to `evidence/screenshots` and short recordings to `evidence/recordings` where they help demonstrate a defect.

## Step 4 - Create a Postman project
Test a safe public practice API. Export the collection into `02-api-testing` and add screenshots showing successful and negative tests.

## Step 5 - Put it on GitHub
Create a repository such as `qa-testing-portfolio`, upload these folders and make the main README your landing page.

## Step 6 - Keep it honest
Remove anything you have not personally completed. The sample documents are scaffolding, not evidence of work you have performed.

## Good First Version
A strong first portfolio only needs:
- One real web-testing project
- 15-20 test cases
- 5-8 genuine bug reports or observations
- One regression checklist
- One Postman API project
- A few basic SQL queries

You do not need a large automation framework before applying for manual QA roles.
